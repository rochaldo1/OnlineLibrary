# Онлайн-библиотека

REST API для управления каталогами книг и книгами внутри них. Backend на ASP.NET Core Web API с PostgreSQL, многослойной архитектурой, валидацией входных данных, единым форматом ошибок, а также unit- и интеграционными тестами.

## Стек

| Назначение | Технологии | 
| --- | --- |
| Платформа | .NET 8, ASP.NET Core Web API |
| Данные | PostgreSQL 17 (Docker), Entity Framework Core 8, Npgsql |
| Валидация | FluentValidation 12 |
| Документация API | Swagger (Swashbuckle), только в окружении Development |
| Тесты | xUnit, NSubstitute, Shouldly, AutoFixture, WebApplicationFactory, Testcontainers |

## Архитектура

Решение разделено на слои, каждый слой это отдельный проект. Зависимости направлены внутрь: слой может ссылаться только на слои, расположенные ниже по списку.

| Проект | Назначение | Зависит от |
| --- | --- | --- |
| `OnlineLibrary.Api` | Контроллеры, обработка ошибок (middleware), фильтр валидации, сборка приложения | Application, Infrastructure |
| `OnlineLibrary.Infrastructure` | `AppDbContext`, конфигурации EF Core, миграции, репозитории | Application |
| `OnlineLibrary.Application` | DTO, валидаторы, сервисы, интерфейсы репозиториев, нормализация текста | Domain |
| `OnlineLibrary.Domain` | Сущности `Catalog` и `Book ` | - |
| `OnlineLibrary.Application.Tests` | Unit-тесты сервисов, валидаторов и нормализации | Application |
| `OnlineLibrary.Api.Tests` | Интеграционные тесты API на настоящей базе Docker | Api |

Application объявляет интерфейсы репозиториев, а Infrastructure их реализует, поэтому бизнес-логика не зависит от EF Core и PostgreSQL. Каждый слой регистрирует свои зависимости через метод расширения (`AddApi`, `AddApplication`, `AddInfrastructure`), а `Program.cs` только связывает их и собирает конвейер.

## Требования

## Запуск

### 1. Клонировать репозиторий

```bash
git clone https://github.com/rochaldo1/OnlineLibrary.git
cd OnlineLibrary
```

### 2. Поднять контейнер с PostgreSQL

Скопируйте `.env.example` в `.env` и заполните значения:

| Переменная | Назначение |
| --- | --- |
| `POSTGRES_USER` | Пользователь базы |
| `POSTGRES_PASSWORD` | Пароль пользователя |
| `POSTGRES_DB` | Имя базы (например, `online_library`) |
| `POSTGRES_HOST_PORT` | Порт на вашем компьютере (обычно `5432`) |

Запустите контейнер:

```bash
docker compose up -d
```

Через несколько секунд `docker compose ps` должен показать статус `healthy`. Порт привязан к `127.0.0.1`, поэтому база доступна только с локального компьютера. Файл `.env` не коммитится.

> Значения `POSTGRES_USER` и `POSTGRES_PASSWORD` применяются только при первом создании тома. Если вы поменяли их позже, пересоздайте том: `docker compose down -v`, затем `docker compose up -d` (данные базы будут удалены).

### 3. Задать строку подключения

Строка подключения читается из ключа `ConnectionStrings:DefaultConnection`. В `appsettings.json` он оставлен пустым, реальное значение задаётся вне репозитория.

Через User Secrets (рекомендуется для разработки):

```bash
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Host=localhost;Port=5432;Database=online_library;Username=<пользователь>;Password=<пароль>" --project OnlineLibrary.Api
```

Или через переменную окружения `ConnectionStrings__DefaultConnection` с тем же значением.

Значения должны совпадать с вашим `.env`. Если строка не задана, приложение не запустится и сообщит, какой ключ отсутствует.

### 4. Запустить приложение

```bash
dotnet run --project OnlineLibrary.Api
```

Или F5 в Visual Studio. В окружении Development:

- миграции применяются автоматически при старте, отдельно создавать таблицы не нужно;
- Swagger UI доступен по адресу: `https://localhost:<порт>/swagger`, порт выводится в консоли при запуске.

Вне Development миграции применяются отдельной командой (нужен инструмент `dotnet-ef`):

```bash
dotnet ef database update --project OnlineLibrary.Infrastructure --startup-project OnlineLibrary.Api
```

## API

### Каталоги

| Метод | Путь | Описание | Ответы |
| --- | --- | --- | --- |
| `GET` | `/api/catalogs` | Список каталогово, отсортированных по названию | 200 |
| `GET` | `/api/catalogs/{id}` | Каталог по идентификатору | 200, 404 |
| `POST` | `/api/catalogs/` | Создание каталога | 201 + `Location`, 400 |
| `PUT` | `/api/catalogs/{id}` | Изменение названия каталога | 200, 400, 404 |
| `DELETE` | `/api/catalogs/{id}` | Удаление каталога вместе с его книгами | 204, 404 |

Запрос на создание и обновление:

```json
{ 
    "name": "Фантастика" 
}
```

Ответ:

```json
{ 
    "id": "3f2a6c1e-8b1d-4a6e-9d2a-1c5b7e9f0a12", 
    "name": "Научная-фантастика"
}
```

### Книги

| Метод | Путь | Описание | Ответы |
| --- | --- | --- | --- |
| `GET` | `/api/catalogs/{catalogId}/books` | Книги каталога, отсортированные по названию; пустой массив, если книг нет | 200, 404 |
| `GET` | `/api/books/{id}` | Книга по идентификатору | 200, 404 |
| `POST` | `/api/books` | Создание книги в каталоге | 201 + `Location`, 400, 404 |
| `PUT` | `/api/books/{id}` | Изменение названия и описания книги, каталог не меняется | 200, 400, 404 |
| `DELETE` | `/api/books/{id}` | Удаление книги | 204, 404 |

Запрос на создание:

```json
{
    "title": "Автостопом по галактике",
    "description": "Научно-фантастическая комедия Дугласа Адамса",
    "catalogId": "3f2a6c1e-8b1d-4a6e-9d2a-1c5b7e9f0a12"
}
```

Запрос на обновление содержит только `title` и `description`.

Ответ:

```json
{
    "id": "9b7d2e40-5c3a-4f1b-8e6d-2a4c6e8f0b13",
    "title": "Автостопом по галактике",
    "description": "Научно-фантастическая комедия Дугласа Адамса",
    "catalogId": "3f2a6c1e-8b1d-4a6e-9d2a-1c5b7e9f0a12"
}
```

`POST /api/books` с `catalogId` несуществующего каталога возвращает 404.

### Правила валидации

| Поле | Правило |
| --- | --- |
| `name` каталога, `title` книги | Обязательно, не пустое и не из одних пробельных сиволов, до 200 символов |
| `description` книги | Необязательно, до 2000 символов |
| `catalogId` книги | Обязателен при создании, не пустой идентификатор |

Пробельные символы по краям текстовых полей обрезаются перед проверкой длины и перед сохранением. Описание, состоящее из одних пробельных символов, сохраняется как `null`.

### Формат ошибок

Все ошибки возвращаются в формате [ProblemDetails](https://www.rfc-editor.org/info/rfc9457/)

Ошибка валидации (400), ключи полей в camelCase:

```json
{
    "title": "Ошибка валидации",
    "status": 400,
    "errors": {
        "name": [ "Название каталога не может быть пустым." ]
    }
}
```

Ресурс не найден (404):

```json
{
    "title": "Не найдено",
    "status": 404,
    "detail": "Сущность 'Каталог' с идентификатором '3f2a6c1e-8b1d-4a6e-9d2a-1c5b7e9f0a12' не найдена."
}
```

Необработанная ошибка (500) возвращает общий текст без технических деталей, подробности пишутся в лог.

## Тесты

```bash
dotnet test
```

Или **Тест -> Обозреватель тестов -> Запустить всё** в Visual Studio.

- **Unit-тесты** (`OnlineLibrary.Application.Tests`) проверяют сервисы с подменой репозиториев, валидаторры и нормализацию текста. Внешних зависимостей не требуют.
- **Интеграционные тесты** (`OnlineLibrary.Api.Tests`) поднимают приложение целиком и одноразовый PostgreSQL в Docker через Testcontainers, отправляют настоящие HTTP-запросы и проверяют ответы, включая каскадное удаление книг на уровне базы. Требуют запущенный Docker Desktop. Первый запуск дольше из-за загрузки образа PostgreSQL. Локальная база из `docker-compose` не затрагивается.

## Решения сверх ТЗ

- Списки каталогов и книг отсортированы по названию, затем по идентификатору, чтобы порядок выдачи был стаблильным;
- Текстовые поля нормализуются: пробельные символы по краям обрезаются, пустое описание сохраняется как `null`;
